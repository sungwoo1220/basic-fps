# Basic FPS: DX11 Windows 시험판

에픽 계정과 언리얼 없이 실행하는 별도 Windows 10/11 x64 시험판이에요. 기존 런처와 브라우저 게임을 설치한 상태 그대로 두고 같은 방에 들어갈 수 있어요. 시험판은 기존 게임을 덮어쓰거나 자동으로 업데이트하지 않아요.

## 실행

1. 저장소 [Releases](https://github.com/sungwoo1220/basic-fps/releases)에서 **Basic FPS DX11 Windows 시험판**의 `BasicFPS-DX11-Win64.zip`을 받아 별도 폴더에 풀어요. 태그는 `dx11-test-`로 시작해요. 서명되지 않은 개인용 빌드이므로 이 저장소에서 받은 파일인지 확인하세요.
2. **기존 Basic FPS 런처**로 방을 열고 기존 게임 창을 켜 둬요. 친구가 만든 방이라면 친구가 알려 준 주소를 사용해요. 시험판에는 방을 직접 여는 기능을 넣지 않았어요.
3. `BasicFPS-DX11.exe` → **방에 연결** → 방 주소와 닉네임 → **계속하기**. 같은 PC에서 연 방은 기본 주소(`http://127.0.0.1:3000`)를 써요. 친구 방은 `http://` 또는 `https://`부터 입력해요.
4. WASD 이동, 마우스 시점, Shift 걷기, 왼쪽 클릭 사격, R 재장전, Tab 점수판, Esc 메뉴를 써요. 내 PC 방에서만 메뉴의 연습 봇 버튼으로 0~6명을 바꿀 수 있어요. 피해·탄약·전적은 기존 방이 판정해요.

## 노트북에서 확인할 것

- 메뉴의 GPU 이름을 확인해요. 외장 GPU를 쓰려면 Windows 그래픽 설정에 런처가 아닌 **`BasicFPS-DX11.exe`**를 추가해요.
- **화면 모드**를 누르면 창모드 → 전체화면 창모드 → 독점 전체화면을 순서대로 바꿔요. 화면이 정상일 때만 **유지**를 누르세요. 15초 안에 선택하지 않거나 전환 중 포커스를 잃으면 이전 모드로 돌아가요. 독점 전체화면은 DXGI가 실제로 독점 상태를 보고할 때만 `DXGI 확인`이 표시돼요. 독점이 풀리면 안전하게 창모드·메뉴로 돌아가요. 재실행하면 창모드에서 시작해요.
- **MSAA**는 끔/2배/4배이며 GPU가 지원하지 않는 단계는 건너뛰어요. DX11 포워드 렌더링과 실제 창 해상도를 사용하며 렌더 배율 조절, FXAA, TAA는 없어요. 같은 위치에서 각 MSAA 단계로 바꾼 뒤 **플레이 중** FPS를 비교하세요. 메뉴는 30FPS 제한이라 비교에 쓰지 않아요.
- FPS 제한은 60/144/240/300/무제한 중에서 선택해요. 프레임 수는 앱이 제출한 프레임 기준으로, 모니터에 실제 표시된 장수나 외장 GPU/MUX 전환을 뜻하지 않아요. 이 시험판은 그래픽 방식과 기존 방 호환을 검증하기 위한 것으로, 기존 게임의 모든 화면이나 설정을 복제하지 않아요.

## 직접 빌드 (선택)

Visual Studio 정식판에서 **C++를 사용한 데스크톱 개발**, Windows SDK, CMake 도구를 설치한 Windows x64에서 실행해요. 빌드에 Epic·언리얼·특정 언리얼용 컴파일러 버전·GitHub runner 연결은 필요 없어요. 기본 CMake가 설치된 Visual Studio를 찾게 두면 돼요. 게임을 직접 빌드하는 데 Node.js는 필요 없고, 기존 방을 개발용으로 직접 열 때만 필요해요.

```powershell
cmake -S dx11 -B dx11/build -A x64
cmake --build dx11/build --config Release --parallel
ctest --test-dir dx11/build -C Release --output-on-failure
.\dx11\build\Release\BasicFPS-DX11.exe
```

GitHub 자동 검사에서 실제 Windows 실행 파일로 임시 방 입장·이동·사격·재장전을 확인하고, 소프트웨어 DX11로 MSAA 끔/2배/4배의 화면을 그려 검사해요. **노트북의 실제 GPU, 독점 전환·복구, 체감 FPS, MUX는 이 검사만으로 확인되지 않아요.**
