# 런처에서 DX11 게임 설치·업데이트·실행 구현 계획

> **에이전트 작업자에게:** 필수 서브 스킬: superpowers:subagent-driven-development(추천) 또는 superpowers:executing-plans로 작업을 하나씩 구현하세요. 단계는 체크박스(`- [ ]`)로 추적합니다.

**목표:** 런처를 켜면 DX11 최신 버전을 자동으로 확인·설치하고, 플레이 버튼 하나로 `BasicFPS-DX11.exe`를 실행한다.

**구조:** `native-update.cjs`의 `NativeClient`를 프로필(언리얼/DX11)로 일반화해 재사용한다. CI가 DX11 릴리스에 `dx11-update.json`과 8MB 조각을 함께 올리고, 런처는 그 목록으로 바뀐 파일만 받는다.

**기술:** Node.js 26(CommonJS), Electron 38, GitHub Actions(`gh`), 기존 `game/tests/*.cjs` 시험(별도 시험 프레임워크 없음, `assert/strict` 사용).

**설계 문서:** `docs/superpowers/specs/2026-11-26-dx11-launcher-design.md`

## 전체 제약
- 언리얼 쪽 공개 시그니처와 한국어 문구는 **한 글자도 바꾸지 않는다**: `pack(source,output,tag)`, `new NativeClient({root,emit,fetch})`, `validateManifest(m)`. 시험이 `/준비 완료/`, `/손상/`, `/달라졌어요/`, `/아직 다운로드할/`, `/이전 시험판으로 복구/`를 정규식으로 검사한다.
- 업데이트 주소는 `https://github.com/sungwoo1220/basic-fps/releases/download/<태그>/<sha256>.bin`만 허용한다. 조각 최대 8MB(`MAX_CHUNK`), 릴리스당 첨부 990개 이하.
- DX11 문구에는 "언리얼"을 쓰지 않는다. DX11은 `BasicFPS-DX11.exe`를 **인수 없이** 실행한다.
- 런처를 닫으면 게임도 종료된다(지금 동작 유지, `before-quit`의 `nativeGame.kill()`).
- 새 파일을 `main.cjs`가 `require`하면 `package.json`의 `build.files`에 추가한다(이번 계획은 새 런타임 파일을 만들지 않는다).
- `npm test`는 매 작업 끝에 통과해야 한다. 시험 실행: Node 26, `NODE_PATH`에 `ws`·`three` 설치 위치 지정.

## 검토 초점 (설계가 암시하지만 작업 시험 밖일 수 있는 것)
1. **오프라인·GitHub 오류(403/네트워크)에서 시작**: 설치본이 있으면 플레이 가능, 없으면 친절한 안내(충돌 금지). → 작업 4 시험.
2. **옛 `dx11-test-*` 릴리스(목록 파일 없음)**: `latest()`가 건너뛰고 새 것을 찾는다. → 작업 1 시험.
3. **설치 파일이 변조됨**: 실행을 거부하고 "달라졌어요" 안내. → 작업 4 시험.
4. **게임 실행 중 업데이트 클릭**: 막고 안내. → 작업 4 시험.
5. **브라우저 게임이 설치되지 않은 PC에서 DX11 플레이**: 정상 실행. → 작업 4 시험.

### 작업 1: `NativeClient` 프로필 일반화
**파일:** 수정 `native-update.cjs`; 새 시험 `game/tests/dx11-update.cjs`
**인터페이스:**
- 생산: `UNREAL`, `DX11` 프로필 객체(내보내기), `validateManifest(m, profile=UNREAL)`, `new NativeClient({root,emit,fetch,progress=()=>{},profile=UNREAL})`. `progress(0..1)`은 설치 중 내려받은 비율로 호출된다.
- 프로필 필드: `kind`, `tagPrefix`(`ue-test-`/`dx11-test-`), `tagPattern`, `manifestName`(`unreal-update.json`/`dx11-update.json`), `folderPrefix`(`ue`/`dx11`), `executablePattern`, `text`(안내·오류 문구 모음).
- `UNREAL`의 값과 `text`는 현재 하드코딩된 값·문구와 **동일**해야 한다. `DX11.executablePattern`은 `/^BasicFPS-DX11\.exe$/`, `kind:'dx11'`, `platform:'win64'` 유지.

- [ ] **1. 실패하는 시험** `game/tests/dx11-update.cjs`: `describe 없이 main()` 형태(기존 시험 관례). `DX11` 프로필로 `validateManifest`가 `{schema:2,kind:'dx11',platform:'win64',version:'0.2.1301',build:'dx11-test-13-1',executable:'BasicFPS-DX11.exe',files:[…]}`를 받아들이고, `kind:'unreal'`·`build:'ue-test-1-1'`·`executable:'room/node.exe'`는 거부함을 단언. `latest()`용 가짜 `fetch`로 릴리스 목록(`dx11-test-12-1` 목록 파일 없음, `dx11-test-13-1` 정상, `build-9-1` 일반 릴리스)에서 13-1만 고르는지, 해당 릴리스가 하나도 없으면 DX11 문구의 "아직 다운로드할" 오류(언리얼 단어 없음)가 나는지 단언.
- [ ] **2. 실행해 실패 확인:** `node game/tests/dx11-update.cjs` → FAIL(`DX11` 미정의).
- [ ] **3. 구현:** `native-update.cjs`의 하드코딩(`folderOK`, 태그 정규식, 폴더 이름 `ue-…`, `ue-test-` 길이 계산, 목록 이름, 실행 파일 검사, 문구)을 프로필로 옮긴다. `latest()`는 `per_page=100`, 최대 3쪽. 설치 루프에서 `progress(done/total)` 호출. 기본값 `UNREAL`.
- [ ] **4. 통과 확인:** `node game/tests/dx11-update.cjs`, `node game/tests/native-update.cjs`, `node game/tests/native-launcher.cjs` 모두 PASS(가짜 `fetch`가 `per_page=20`을 검사하면 그 부분만 맞춰 고친다).
- [ ] **5. 커밋:** `git add native-update.cjs game/tests/dx11-update.cjs && git commit -m "Generalize NativeClient with Unreal and DX11 profiles"`

### 작업 4: 런처에 DX11 설치·업데이트·실행 추가
**파일:** 수정 `main.cjs`, `preload.cjs`, `index.html`, `ui.js`; 시험 `game/tests/native-launcher.cjs`(추가)
**인터페이스:**
- 소비: 작업 1의 `NativeClient`, `DX11`.
- 생산: IPC `play`가 `client:'dx11'`을 받는다(기본값). 새 이벤트 `dx11-state` `{installed:boolean,version:string|null,busy:boolean}`와 `progress`(0~1). 새 핸들러 `dx11-update`. 시작 시(`did-finish-load`) **DX11 먼저, 그다음 브라우저 `update()`**.
- 동작: DX11 `NativeClient`는 `path.join(app.getPath('userData'),'dx11')`. 플레이는 `dx11.verifyLaunch()` 후 `spawn(executable,[],{cwd:경로,windowsHide:false,stdio:'ignore',shell:false})`, `nativeGame`에 보관, 시작 후 15초 안에 오류·비정상 종료면 `dx11.rollback()`. 브라우저 설치 여부와 `host`를 검사하지 않는다. 모르는 `client`는 `dx11`로, `browser`·`unreal`은 기존 경로 유지. 게임 실행 중 `dx11-update`는 기존 "게임을 종료한 뒤" 안내로 막는다.
- 화면: 큰 `#playDx11` 버튼(문구 "플레이"), 설치 버전, 상태 줄, `<progress id="bar">`. 기존 게임 선택·방 열기·서버 주소·수동 업데이트 버튼은 `<details>`("고급")으로 옮기고 기존 id와 `ui.js` 동작은 유지. 인터넷이 없어도 설치본이 있으면 `#playDx11`을 켠다. 플레이 누르면 "파일 확인 중…" 문구.

- [ ] **1. 실패하는 시험** (`native-launcher.cjs`, 기존 가짜 Electron·`child_process` 재사용): 임시 폴더에서 `pack`(작업 2) → `NativeClient({root:userData/dx11,profile:DX11}).install(manifest)` → `main.cjs` 로드(브라우저 게임 **없음**). 단언: `handlers.play(null,{client:'dx11'})` → 자식 1개, `args`가 `[]`, `options.shell===false`; 연타해도 1개; 실행 중 `handlers['dx11-update']()` → `/게임을 종료한 뒤|게임이나 다른 업데이트/`; 종료 후 재실행 가능; 실행 파일을 `tampered`로 바꾸면 자식 수 그대로 + `/달라졌어요/`; 새 버전 설치 후 실행 → `error`+`exit 1` 시 이전 폴더로 복구(`/이전 버전으로 복구/` 같은 DX11 문구). 설치본이 없을 때 `play`는 충돌 없이 안내만 한다.
- [ ] **2. 실패 확인:** `node game/tests/native-launcher.cjs` → FAIL.
- [ ] **3. 구현** (위 인터페이스대로). `main.cjs:231`·`:236`의 브라우저 설치 가드를 client별로 나누고, `:254`의 언리얼 인수와 `:257`의 복구 대상을 client별로 분기.
- [ ] **4. 화면 구현:** `index.html`/`ui.js`/`preload.cjs`. 기존 `native-launcher.cjs`·`launcher.cjs` 시험이 쓰는 핸들러 이름은 바꾸지 않는다.
- [ ] **5. 통과 확인:** `npm test` 전체 PASS.
